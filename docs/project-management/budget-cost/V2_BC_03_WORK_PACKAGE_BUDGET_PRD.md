# V2 预算与成本 03：工作包预算分解产品需求

## 1. 目标与边界

在已批准的项目分类预算之下，将预算分配到实际执行的工作包，形成“工作包 × 成本类别”的受控预算明细。工作包预算解决预算由谁执行、还有多少待分配的问题；它不登记实际成本，也不产生预算占用或财务凭证。

- 金额统一为人民币含税，保留两位小数。
- 仅 `WORK_PACKAGE` 工作包可拥有预算；汇总 WBS、任务和交付物不提供预算入口。
- 工作包预算不是普通编辑字段。查看入口位于工作包详情抽屉的“预算”页签，新增、调整和删除均通过项目变更单审批并由项目负责人确认应用。
- 本阶段不做实际成本、预算占用、采购承诺、工时成本、财务同步、多币种、税率和税额拆分。

## 2. 模型与术语

| 术语 | 定义 |
| --- | --- |
| 项目分类预算 | 阶段 2 已批准的“项目 × 成本类别”预算总额，是本阶段的可分配上限。 |
| 工作包预算 | “工作包 × 成本类别”的预算分配行，是本阶段最小业务明细。 |
| 已分配 | 某项目成本类别下，全部工作包预算行的金额合计。 |
| 待分配 | 项目分类预算减去已分配金额；允许为正数，不允许为负数。 |
| 分配变更 | 对工作包预算行的新增、调整或删除，使用 `PLAN_CHANGE` 审批。 |

同一项目、同一工作包、同一成本类别只能有一条工作包预算行。一个工作包可分配多个成本类别；一个成本类别也可分配给多个工作包。

## 3. 核心规则

### 3.1 分配约束

- 项目必须启用预算，且当前成本类别存在有效的项目分类预算，才可向工作包分配该类别预算。
- 工作包预算金额必须大于 0，测算依据必填。
- 每个成本类别下，工作包预算合计不得大于项目分类预算；未分配金额允许保留在项目级。
- 项目分类预算调减后不得低于该类别已分配金额；删除项目分类预算前必须删除该类别全部工作包预算。
- 停用成本类别不允许新增工作包预算或调增金额；允许调减或删除历史预算行。
- 项目取消预算前必须删除全部项目分类预算和工作包预算；未来接入占用或实际成本后，再追加不可取消规则。

### 3.2 工作包生命周期约束

- 仅属于当前项目、节点类型为 `WORK_PACKAGE` 的节点可成为预算对象。
- 已完成工作包的预算只读，不允许新增、调增或修改依据；允许在同一变更单中删除的例外不开放，避免破坏历史执行口径。
- 新增工作包与预算分配必须使用两张独立变更单：先完成工作包变更的审批与确认应用，取得正式工作包后，才可发起该工作包的预算分配变更。新增工作包变更不携带预算、交付物或其他后续执行数据。
- 删除工作包前必须不存在工作包预算；如需删除，须在同一变更单中先删除该工作包的全部预算行，且仍满足既有任务、交付物、问题等删除限制。
- WBS/工作包变更不得改变已有工作包预算的归属；现有节点不可跨父级移动。

## 4. 页面与交互

### 4.1 项目预算页签

项目工作区的“项目预算”页签扩展两层信息：

1. 分类汇总表：成本类别、项目分类预算、已分配、待分配、分配率和状态；
2. 工作包分配表：按成本类别或工作包展开，展示工作包名称、分配金额、测算依据和最近变更信息。

页面保留“发起预算分配变更”入口，进入项目变更中心并定位 `WORK_PACKAGE_BUDGET` 模块。

### 4.2 工作包详情抽屉

工作包详情新增“预算”页签，仅用于查看：

- 工作包预算合计、成本类别数量；
- 明细表：成本类别、分配预算、测算依据、项目分类预算、全项目已分配、待分配；
- “发起预算分配变更”按钮：自动带入项目、工作包和模块上下文。

抽屉内不提供直接新增、保存或删除金额的能力。

### 4.3 项目变更编辑器

新增模块 `WORK_PACKAGE_BUDGET`。每一条预算行是一个最小变更项：

| 操作 | 变更对象 | 输入 |
| --- | --- | --- |
| ADD | 工作包 + 成本类别 | 分配金额、测算依据 |
| UPDATE | 已有工作包预算行 | 分配金额或测算依据（至少变更一项） |
| DELETE | 已有工作包预算行 | 无新值，仅填写本项变更说明 |

编辑器以工作包树选择对象，仅展示工作包；成本类别选项仅展示当前项目存在项目分类预算的有效末级类别，并实时过滤已分配类别。核对、审批详情和基线比较按模块、工作包、成本类别逐字段显示差异，禁止展示 JSON。

## 5. 审批、应用与基线

1. 草稿可保存不完整的工作包分配，但不允许零金额、重复行或无测算依据。
2. 提交审批与确认应用前均在内存模拟整张变更单的预算最终态，校验类别上限、工作包状态和删除关联；工作包预算只引用已正式存在的工作包。
3. 审批通过不立即修改正式预算；项目负责人确认应用时，在事务中应用全部变更。任一预算行失败则整体回滚。
4. 成功应用后生成新计划基线；快照同时保存项目分类预算与工作包预算。版本比较新增“工作包预算”分组。

## 6. 权限与数据范围

- 查看工作包预算沿用工作包/项目的数据范围：项目成员、项目负责人、申请人、审批人及既有可查看用户。
- 发起、编辑、提交、撤回沿用项目变更单能力字段；确认应用仅项目负责人。
- 管理员不是业务越权特例。
- 现阶段保留项目管理接口注解权限临时关闭状态，服务层项目数据范围与业务能力校验不可绕过。

## 7. 本阶段不做

- 任务级、交付物级预算；
- 预算占用、采购申请、合同、报销、实际成本和工时成本；
- 自动按任务、工时或交付物比例分摊；
- 预算从工作包向项目自动回写；
- 工作包预算独立审批流或独立版本体系。
