# 项目管理系统多角色流程审计（2026-09-04）

## 1. 审计结论

结论：**核心业务链路有条件合格，可用于受控试运行；暂不建议按“完整、成熟的项目管理系统”正式验收通过。**

系统已经具备立项、审批、团队、WBS、工作包、任务、交付物、问题、变更、基线、预算、三类实际成本和工时归集的主干闭环。尤其是项目预算页，已经能较直观地回答“预算多少、分到哪里、实际花了多少、成本从哪里来”。

但本轮从项目负责人、项目成员、工时审批人、成本管理员和采购专员视角复核后，仍发现 5 项管理/流程 P1 和 9 项管理/流程 P2/P3；随后追加的 UI / 布局专项又登记 1 项 P1、7 项 P2 和 1 项 P3。主要风险集中在：

1. WBS 与日期数据可以在项目运行过程中重新变得不完整或互相矛盾；
2. 普通成员可看到其他人员的小时单价和个人人工成本；
3. 项目完成门槛不包含财务、审批和复盘关闭条件；
4. 风险仍是立项文本，不是可跟踪的风险台账；
5. 采购单据与项目实际成本之间缺少双向可点击追溯。
6. 采购入库/到货详情在固定窄抽屉内展示 14–15 列明细，字段被压成逐字换行，不能可靠完成单据核对。

本轮只做审计和记录，没有审批、删除、修改业务状态或创建测试单据。采购成本分摊按当前约定不纳入本轮优化范围。

## 4. 多角色体验判断

### 4.1 项目负责人

做得好的地方：

- 项目工作区按立项、概览、团队、计划、预算、工时、交付物和问题组织，主对象齐全。
- 预算页可一屏看到 1,290,000 元总预算、1,015,000 元工作包预算、275,000 元未分配预算、38,935 元实际成本和三类来源构成。
- 项目工时可以按工作包、任务、人员、日期查看，并与 2,515 元内部人工成本一致。
- 项目变更和计划基线完整保留；项目 1 当前存在 V1 至 V18 基线。

不足：概览页只有任务、交付物和问题比率，没有逾期任务、关键里程碑偏差、预算/成本健康、未决变更、待审批和风险暴露。管理者需要逐个页签寻找异常，不能在一个页面判断项目是否健康。

### 4.2 项目成员 / 工时填报人

做得好的地方：

- “我的任务”显示项目、工作包、任务、日期、状态，并提供开始、查看计划和填报工时入口。
- 工时按自然周填报，任务关联清晰，审批归档后回写实际工时和成本。

不足：个人工时已归档页面以禁用表单呈现，没有醒目的周单状态、审批流和归档时间；“我的工时”同时存在个人路由和项目管理菜单路由，信息架构不够统一。

### 4.3 工时审批人

做得好的地方：

- 审批中心区分待我审批、我发起的、我已处理；业务审批保留结构化工时明细。
- 工作台能看到自己的逾期任务。

不足：工作台没有“待审批数量”卡片，审批人只能依赖通知角标或进入“我的审批”后确认；工时审批与任务待办混在不同入口，优先级不直观。

### 4.4 成本管理员

做得好的地方：

- 人工单价按人员和有效期维护，重叠有效期受约束。
- 全局工时管理能查看项目、工作包、任务、人员、审批状态和成本归集状态。

不足：全局工时管理没有显示本条工时的小时单价和成本金额，也缺少人员、工作包、日期、成本状态筛选，不能高效完成待计价、待归集和金额核对。

### 4.5 采购专员

做得好的地方：

- 采购订单列表能看到归属项目。
- 到货和入库详情逐行保留项目、成本类别、物料、数量、含税单价和金额。
- 入库成本能在项目预算中按 `PURCHASE_INBOUND`、入库单号和行号追溯。

不足：已审核采购订单没有只读详情入口；选中后“修改”按钮反而会激活，点击才返回“当前操作没有权限”。到货/入库列表没有项目和成本类别，入库详情也不显示项目成本生成状态或跳转项目预算的入口。

## 5. 本轮新发现问题

### PM-RVW-001：执行中项目的 WBS 仍可处于不完整或日期矛盾状态

- 类型：BUG / DATA / BIZ
- 优先级：P1
- 角色：项目负责人
- 证据：项目 1 的汇总 WBS `3 环境可靠性验证` 无计划日期、无下级工作包；汇总 WBS `1 硬件与嵌入式研发` 计划结束为 `2026-09-30`，子工作包 `1.2 固件与协议适配` 结束为 `2026-10-31`。
- 原因判断：启动检查只在启动时验证空汇总分支；执行中新增/变更 WBS 后没有再次执行整棵树健康检查。汇总 WBS 日期不是必填，子工作包也没有校验必须处于父汇总 WBS 周期内。
- 影响：WBS 无法作为可信计划基线，甘特图、逾期判断和阶段进度可能失真。
- 建议：新增可复用的“计划健康检查”，在启动、变更提交、变更应用和项目完成前执行；汇总 WBS 日期可由子项自动汇总，或明确要求必填并校验父子日期覆盖关系。

### PM-RVW-002：普通项目成员可查看他人的小时单价和个人人工成本

- 类型：SECURITY / BIZ
- 优先级：P1
- 角色：项目成员
- 证据：以 `csy` 打开项目 1 的“项目工时”，可看到 `zxl`、`hours_approver` 等人员的工时说明、人工成本以及 `210.00 元/小时`、`199.99 元/小时` 等单价。
- 影响：内部结算单价通常属于成本敏感信息；当前范围大于“项目负责人查看授权项目、成本管理员查看全量”的产品口径。
- 建议：将项目工时返回拆成三档：普通成员仅看本人明细和项目/任务聚合工时；项目负责人看人员工时但不一定看单价；成本管理员看完整单价和成本。最终口径需业务确认。

### PM-RVW-003：实际成本允许登记未来日期和项目结束后的日期

- 类型：BIZ / VALIDATION
- 优先级：P1
- 角色：项目负责人、成本管理员
- 证据：项目 1 计划结束为 `2026-11-30`，当前日期为 `2026-09-04`，实际成本列表存在 `2027-02-10` 的 20,000 元手工成本，状态为“有效”。
- 影响：未来承诺被当成已经发生的实际成本，导致成本执行口径不可信，也会把项目结束后的费用计入当前项目。
- 建议：实际成本发生日期默认不得晚于当前业务日期，并应落在允许的项目成本期间；如确实需要未来费用，应新增“承诺成本/预计成本”，不要复用实际成本。

### PM-RVW-004：项目完成门槛没有覆盖财务、审批和复盘关闭

- 类型：GAP / BIZ
- 优先级：P1
- 角色：项目负责人、管理层、成本管理员
- 证据：当前完成动作只检查“全部工作包已完成”和“无未关闭问题”。没有检查待审批工时、待计价/待归集工时、未应用变更、预算和实际成本对账、采购未结单、结项报告、经验复盘或遗留事项批准。
- 影响：系统中的“已完成”更接近执行任务结束，不等于项目管理和财务意义上的关闭。
- 建议：把 `COMPLETED` 拆为“待关闭/已关闭”，增加可配置关闭清单和负责人确认；至少包含计划、交付、问题、工时、成本、采购、变更、复盘和遗留事项。

### PM-RVW-005：缺少执行期风险台账和风险闭环

- 类型：GAP
- 优先级：P1
- 角色：项目负责人、管理层
- 证据：完整项目信息仅显示立项时的“主要风险”静态文本；系统没有风险编号、责任人、概率、影响、应对措施、触发器、剩余风险、状态和风险转问题流程。
- 影响：项目概览显示未关闭问题为 0 时，仍可能有高暴露风险，但管理者无法从系统识别。
- 建议：新增项目风险登记册，并在概览展示高风险数量、逾期应对措施和风险趋势；支持风险转问题并保留关联。

### PM-RVW-006：管理概览不能一次判断项目健康度

- 类型：UX / GAP
- 优先级：P2
- 角色：项目负责人、管理层
- 证据：概览只展示执行任务数、完成任务数、待批准交付物、未关闭问题及三项比率；项目 1 实际存在逾期未开始任务、空 WBS、未分配预算和未来实际成本，概览均未提示。
- 建议：增加红黄绿健康摘要：里程碑/逾期、WBS 健康、预算分配、成本偏差、未决变更、待审批、风险和交付延期，并允许直接下钻。

### PM-RVW-007：启用预算的项目可以在 0 工作包分配下启动

- 类型：BIZ / GOVERNANCE
- 优先级：P2
- 角色：项目负责人、管理层、成本管理员
- 证据：项目 35 `budget_required=1`、项目分类预算 480,000 元、工作包预算 0 元，但项目状态为执行中。
- 影响：所有预算都停留在项目级，无法确定哪个工作包承担预算责任，也无法对工作包成本进行控制。
- 建议：保留项目级预备费是合理的，但应配置最低分配率或对关键成本类别要求至少分配到一个工作包；启动检查至少应明确警告并要求负责人确认。

### PM-RVW-008：计划进度缺少工时/权重基础

- 类型：BIZ / DATA
- 优先级：P2
- 角色：项目负责人、项目成员
- 证据：项目 1 多数执行任务的预计工时为空，当前项目任务完成率按任务数量/简单平均展示为 17%。
- 影响：一个 2 小时任务和一个 200 小时任务权重相同，管理层看到的进度可能与真实工作量严重偏离。
- 建议：执行任务至少维护预计工时或计划权重；项目/工作包进度支持按预计工时加权，并同时展示“任务数口径”和“工时口径”。

### PM-RVW-009：成本管理员的全局工时台账不足以完成成本核对

- 类型：UX / GAP
- 优先级：P2
- 角色：成本管理员
- 证据：全局“工时管理”只显示工时和成本状态，不显示小时单价、成本金额；筛选只有项目、任务和审批状态。
- 建议：补充人员、工作包、日期区间、成本状态筛选，以及单价快照、成本金额、来源周单、实际成本编号；增加待计价/待归集快捷视图和汇总金额。

### PM-RVW-010：采购单据与项目成本缺少双向导航和过账状态

- 类型：UX / GAP
- 优先级：P2
- 角色：采购专员、项目负责人、成本管理员
- 证据：到货/入库详情有项目和成本类别；项目成本有入库单号和行号，但二者都不是可点击的业务跳转。入库详情没有显示是否已生成/冲销项目成本。
- 建议：入库行显示“项目成本：已归集/已冲销/失败”并可跳转实际成本；项目实际成本的来源单号可跳转入库详情。

### PM-RVW-011：已审核采购订单的只读详情入口缺失，按钮能力反馈不一致

- 类型：BUG / UX
- 优先级：P2
- 角色：采购专员
- 证据：订单列表中的已审核单据没有“详情”操作。选中已审核订单后，“修改”“删除”按钮从禁用变为可用；点击“修改”后才提示“当前操作没有权限”。
- 影响：采购人员无法从订单端查看已冻结的项目和成本类别快照，且界面诱导执行无权限操作。
- 建议：始终提供只读详情；按钮按单据状态和服务端能力字段禁用/隐藏，并显示不可操作原因。

### PM-RVW-012：个人工时归档状态和审批历史不够清晰

- 类型：UX
- 优先级：P2
- 角色：项目成员、工时审批人
- 证据：`csy` 的已归档更正周单以整页禁用表单显示，但页面没有醒目的“已归档”状态、审批通过时间、审批人和审批流程入口。
- 建议：在周单顶部增加状态条、周总工时、提交/审批/归档时间线和更正关联；禁用原因应直接说明。

### PM-RVW-013：基线来源对业务人员不够友好

- 类型：UX
- 优先级：P3
- 角色：项目负责人、审批人
- 证据：计划基线列表的“来源变更单”显示 `81`、`80`、`45` 等数据库数字，不能直接看到变更编码、标题、模块或打开变更单。
- 建议：展示变更编码和标题，增加可点击链接及变更模块摘要；版本列表支持按时间和模块筛选。

### PM-RVW-014：项目交付物与 BOM/图纸仍缺少版本级业务绑定

- 类型：GAP
- 优先级：P2
- 角色：项目负责人、硬件负责人、质量/交付审核人
- 证据：BOM 现已支持图纸附件，但项目交付物列表的“交付对象”仍为空；系统不能证明某次“工程 BOM/图纸”交付对应哪一个 BOM 主数据和版本。
- 建议：交付物支持绑定 `BOM_VERSION` 等业务对象，保存对象主键、编码、版本和审核状态快照；交付审批通过后冻结版本引用，并允许从项目交付物跳转 BOM 详情及图纸附件。

## 6. 已确认合理的成本口径

当前三类实际成本来源及归属方式如下：

| 来源 | 当前关联 | 评价 |
| --- | --- | --- |
| 手工登记 `MANUAL` | 项目 + 成本类别 + 可选工作包 | 合理，但必须补发生日期约束 |
| 工时归集 `WORK_HOURS` | 项目 + 工作包 + 执行任务 + 人员单价快照 | 关联完整；需收紧个人单价可见范围 |
| 采购入库 `PURCHASE_INBOUND` | 采购订单选择项目和成本类别，到货/入库继承，入库行形成项目级实际成本 | 数据口径合理；当前不分摊工作包，符合本轮约定 |

采购入库成本目前属于项目分类预算下的项目级实际成本，`work_package_id = null`。本轮不做采购成本分摊；后续若恢复该需求，应单独设计分摊单、分摊规则、撤销/重算和审计记录，不建议直接修改已经过账的入库成本原始归属。

## 7. 建议优化顺序

### 第一批：发布前应处理

1. PM-RVW-002：工时单价和个人成本可见范围。
2. PM-RVW-001：WBS 整树健康检查、父子日期和空分支。
3. PM-RVW-003：未来/项目期外实际成本。
4. PM-RVW-004：项目关闭门槛。
5. PM-RVW-005：风险台账的最小可用闭环。
6. PM-UI-006：采购入库/到货详情宽表可读性和核对能力。

### 第二批：提升管理效率

1. PM-RVW-006：项目健康总览。
2. PM-RVW-007、008：预算责任和工时加权进度。

## 8. 建议的正式验收门槛

满足以下条件后，可将结论从“有条件合格”提升为“完整项目管理合格”：

- P1 项全部完成并通过角色隔离回归；
- 任何执行中项目都通过 WBS、日期、责任人、交付和预算健康检查；
- 管理概览可以直接识别逾期、预算异常、风险和待审批；
- 项目关闭包含工时、成本、采购、变更、交付、问题和复盘清单；
- 采购入库成本和工时成本均能从来源单据双向跳转；
- 项目交付物可绑定受控业务对象版本，至少覆盖 BOM 和图纸。
- 采购、预算、工时、审批、交付、WBS 和变更宽表在 1920×1080、1440×900、1366×768 及 125% 缩放下均不出现逐字换行，且横向滚动、固定列和长文本展开可用。

## 9. UI / 布局专项补充结论

本轮使用 Computer Use 在本地 Chrome 实际复核了采购入库、采购到货、采购订单、项目预算、项目工时、我的任务、我的待交付和我的审批，并对对应前端实现做了静态核对。

结论分为三类：

1. **确定不合格**：采购入库/到货详情，以及新增入库单宽表。用户截图中的逐字换行已稳定复现，根因是固定 760/980px 容器内放置 14–16 列且没有横向滚动和列宽保护。
2. **有条件可用**：项目预算、实际成本和项目工时在本轮 1829×920 画布下基本可读，但逻辑宽度和滚动配置不稳定，较窄视口仍有压缩风险；“我的任务”操作列已经在当前宽度发生多行换行。
3. **当前表现良好**：采购三个列表页和“我的待交付”列表使用了较完整的列宽、横向滚动及长文本省略策略，可作为其他表格改造的参考。
