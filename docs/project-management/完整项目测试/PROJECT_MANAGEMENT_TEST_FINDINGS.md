## 1. 文档用途

本文件只记录全量测试过程中发现的问题，不代替 PRD 或验收清单。以下内容均应记录，即使功能最终可以完成：

- 程序报错、数据错误、状态错误和权限绕过；
- 页面布局、信息层级、主题色、尺寸、截断和响应式问题；
- 操作步骤割裂、反馈不明确、重复录入和容易误操作的问题；
- 与真实制造业研发项目不匹配的字段、规则或流程；
- 当前产品无法形成真实闭环的能力缺口。

首轮测试以记录为主。除 P0 阻断主链路外，不在测试中途直接修改；首轮完成后统一评审、修复和回归。

## 2. 优先级和处理方式

| 级别 | 定义                                          | 处理要求                           |
| ---- | --------------------------------------------- | ---------------------------------- |
| P0   | 数据损坏、严重越权、主流程完全无法继续        | 立即登记；修复并回归后才继续主链路 |
| P1   | 核心功能失败、金额/状态错误、重要业务规则缺失 | 首轮结束后第一批修复，必须回归     |
| P2   | 有替代路径但明显影响效率、理解或真实性        | 统一评审后修复或明确排期           |
| P3   | 视觉细节、文案、低频易用性改善                | 集中优化，允许有明确延期结论       |

处理状态：`新发现`、`待确认`、`已确认`、`修复中`、`待回归`、`已关闭`、`接受现状`、`延期`。
