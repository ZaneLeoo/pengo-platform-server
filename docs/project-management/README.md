# 项目管理

状态：产品总纲  
最后核对：2026-08-25  
适用分支：`project-management`

本文是项目管理模块的唯一产品总文档，用来说明产品方向、业务边界、版本划分和当前进度。详细代码行为以实现为准；版本是否完成以对应验收文档为准。

## 要实现什么

面向离散制造研发项目，建立从项目申请、立项审批、团队组建、范围与计划编制，到任务执行、正式交付、问题控制和项目关闭的统一协作与追溯平台。

产品需要持续回答四个问题：

1. 项目为什么立项，要交付什么？
2. 谁负责，计划如何完成？
3. 当前执行到哪里，存在哪些偏差和问题？
4. 项目是否已经满足交付和关闭条件？

## 主要用户

| 用户 | 主要工作 |
| --- | --- |
| 项目申请人 | 编写立项申请、初步计划和支撑材料 |
| 立项审批人 | 审查申请版本并批准或退回 |
| 项目负责人 | 组建团队、编制计划、启动和控制项目 |
| 工作包负责人 | 负责范围、任务组织、正式交付和验收 |
| 任务执行人 | 推进本人任务并维护过程成果 |
| 交付审核人 | 审核需要批准的正式交付物 |
| 项目成员 | 查看参与项目并登记、跟踪问题 |
| 配置管理员 | 维护分类、专业角色和交付物类型 |

## 业务主线

```text
项目申请
  → 立项审批
  → 团队组建
  → WBS、工作包、任务和交付要求
  → 启动检查
  → 任务执行与问题跟踪
  → 正式交付
  → 项目完成与关闭
```

## 核心模型

```text
项目
├── 立项申请版本：初步计划、材料、审批记录
├── 项目成员
├── WBS 范围树
│   ├── 汇总 WBS
│   └── 工作包
│       ├── 任务树：汇总任务、执行任务、任务成果
│       └── 正式交付物：提交版本、审核记录
└── 问题
```

关键边界：

- WBS 说明“项目必须交付什么”，任务说明“工作包如何执行”。
- 工作包是 WBS 叶子和最低范围管理单元。
- 正式交付物属于工作包；任务成果只是过程文件或工作证据。
- 系统用户是人员身份来源；项目成员表示用户参与具体项目的关系。
- 状态通过受控生命周期动作改变，不能作为普通字段随意编辑。

WBS 与任务分离的设计原因见 [ADR-0001](../adr/0001-separate-wbs-and-task.md)。

## 版本路线

| 阶段 | 目标 | 关键产出 | 当前状态 |
| --- | --- | --- | --- |
| V1 | 跑通基础执行闭环 | 立项、团队、WBS、任务、交付物、问题、完成 | 功能已实现，待系统验收 |
| V1 收尾 | 证明基础闭环可靠 | 权限、异常、回归、部署说明 | 当前阶段 |
| V2 | 建立项目控制闭环 | 问题闭环、通用审批、基线、变更、验收与关闭 | 开发中 |
| 后续 | 提升管理能力 | 甘特图、风险、工时、成本、资源与项目组合 | 未排期 |

## 当前实现

已经具备：

- 项目分类、专业角色、交付物类型配置
- 立项申请、初步计划、附件、提交、审批和退回
- 项目团队、项目角色、专业角色和成员退出
- WBS、工作包、汇总任务、执行任务和正式交付要求
- 项目及任务的启动、暂停、恢复和完成
- 我的项目、我的任务、任务成果和操作记录
- 正式交付物提交、审核、版本历史和我的待交付
- 问题跟踪、项目工作台和项目启动前就绪检查
- 可配置的串行审批流、统一审批中心，以及立项和正式交付物接入
- 项目计划基线、版本比较、计划变更单、`PLAN_CHANGE` 审批、负责人确认应用与基线冲突重核（待验收）
- 问题提出人、负责人、逾期、受控状态流转、评论、附件与活动时间线

当前尚未具备：

- 任务依赖、关键路径和甘特图
- 独立风险登记册
- 完整工时与实际成本管理
- 工作包正式验收、项目关闭审批和复盘归档

## 当前工作方法

1. 先执行 [V1 验收](V1_ACCEPTANCE.md)，发现阻断缺陷并完成 V1 收尾。
2. V1 验收通过后，按 [V2](V2.md) 的待决策问题确认首个迭代；已确定的计划基线与变更专题以 [V2 变更 PRD](V2_CHANGE_PRD.md) 为准。
3. 新功能必须先写清用户、规则、异常和验收条件，再进入开发。
4. 日常迭代不新增重复的需求文档；复杂专题需要讨论时，才增加一份短专题文档。
