# 项目管理 V1 验收

状态：待执行  
最后更新：2026-08-25

本文件是判断 V1 是否完成的唯一验收清单。验收时填写环境、执行人、日期、结果和缺陷编号；不要另建重复的验收报告。

## 完成定义

V1 完成必须同时满足：

- 下列主流程全部通过。
- P0 缺陷全部关闭。
- P1 缺陷有明确处理结论且不阻塞发布。
- 至少使用申请人、审批人、项目负责人、任务执行人和非项目成员等非超级管理员账号验证权限。
- 数据库可以通过明确且经过验证的方式部署或升级。
- 生命周期、冻结和越权等高风险规则具备自动化测试，或保留可重复的人工验收证据。

## 1. 立项

- [ ] 创建项目草稿成功，重复项目编码被拒绝。
- [ ] 立项目标、背景、范围、预期成果、资源、风险和可行性可以保存并正确回显。
- [ ] 初步计划日期必须位于项目计划日期内。
- [ ] 支撑材料可以按申请区段上传、查看和删除。
- [ ] 缺少关键内容时不能提交，系统一次性提示全部缺失项。
- [ ] 提交后项目进入审批中，并冻结申请、初步计划和附件。
- [ ] 审批通过后项目进入已批准；审批退回后恢复草稿并允许修订。
- [ ] 退回后重新提交生成新审批版本，旧版本和旧附件仍可查询。
- [ ] 无审批权限用户不能审批，审批人不能通过普通编辑直接改变状态。

## 2. 团队

- [ ] 项目负责人对应有效系统用户，并自动成为有效项目成员。
- [ ] 可以添加成员并设置项目角色、专业角色和职责。
- [ ] 同一有效用户不能重复加入同一项目。
- [ ] 已退出成员不再出现在新的工作包和任务负责人候选项中。
- [ ] 项目负责人不能直接退出，必须先变更负责人。
- [ ] 无项目编辑权限用户不能维护团队。

## 3. 计划

- [ ] 汇总 WBS 可以继续拆分，但不能直接承载任务或正式交付物。
- [ ] 工作包是叶子节点，不能继续添加 WBS 子节点。
- [ ] 任务必须属于同一项目的工作包，不能跨项目挂接。
- [ ] 汇总任务可以包含子任务；执行任务必须指定有效项目成员。
- [ ] 工作包和任务日期满足项目、父级和自身日期约束。
- [ ] 工作包可以配置范围、负责人、验收标准、完成定义和正式交付要求。
- [ ] 声明需要交付的工作包至少包含一项必交正式交付物。
- [ ] 交付物类型和格式配置变化不覆盖既有项目快照。

## 4. 启动

- [ ] 只有已批准项目可以启动。
- [ ] 就绪检查覆盖团队、工作包、任务、负责人、日期和正式交付要求。
- [ ] 就绪检查一次性返回全部缺失项。
- [ ] 项目启动成功后进入执行中并记录实际启动日期。
- [ ] 启动后不能新增、删除或改变 WBS、任务结构和正式交付要求。
- [ ] 草稿、审批中、暂停和已完成项目不能重复启动。

## 5. 任务执行

- [ ] 执行任务能够按“开始 → 暂停 → 恢复 → 完成”合法流转。
- [ ] 暂停必须填写原因，非法状态动作被拒绝。
- [ ] 每次动作记录操作人、前后状态、时间和暂停原因。
- [ ] 只有任务执行人可以推进任务和增删任务成果。
- [ ] 完成任务后进度为 100%，并记录实际完成日期。
- [ ] 汇总任务、工作包和上级 WBS 的状态与进度正确聚合。
- [ ] 项目暂停或完成后，任务动作按业务规则受到限制。

## 6. 正式交付

- [ ] 文件型交付物限制允许格式；链接型交付物要求有效链接。
- [ ] 只有责任人可以提交正式交付物。
- [ ] 每次提交生成递增版本，历史版本不被覆盖。
- [ ] 无需审核的交付物提交后直接满足交付条件。
- [ ] 需要审核的交付物进入待审核，只有审核人可以批准或退回。
- [ ] 退回记录审核意见，再次提交形成新版本。
- [ ] “我的待交付”只显示当前用户负责且尚未满足条件的项目交付物。
- [ ] 正式交付物与任务成果在页面、接口和数据上保持分离。

## 7. 问题与工作台

- [ ] 问题可以按项目、状态和严重程度查询。
- [ ] 问题能够按 `OPEN → PROCESSING → RESOLVED → CLOSED` 推进。
- [ ] 非项目成员和无权限用户不能访问或修改超出授权范围的问题。
- [ ] 立项审批期间的问题写入符合冻结规则。
- [ ] 工作台的我的项目、待完成任务、待交付和未关闭问题与明细一致。
- [ ] 数据库存在异常空 path 菜单时，前端忽略异常菜单且其余路由仍能加载。

## 8. 项目暂停与完成

- [ ] 执行中项目可以暂停，暂停必须填写原因。
- [ ] 暂停项目可以恢复执行，其他状态不能执行恢复。
- [ ] 存在未完成执行任务时项目不能完成。
- [ ] 存在未满足的必交正式交付物时项目不能完成。
- [ ] 全部条件满足后项目进入已完成并记录实际完成日期。
- [ ] 已完成项目不能继续修改计划结构或推进任务。
- [ ] “未关闭问题是否阻止项目完成”已经得到业务确认并与实现一致。

## 9. 部署与回归

- [ ] 明确本次环境需要执行的 SQL，不按 01–38 无差别执行。
- [ ] 未在生产环境执行演示账号、演示项目或破坏性身份迁移脚本。
- [ ] 核心列表分页、项目计划树、文件上传和动态菜单在目标环境正常。
- [ ] 后端编译、前端 lint、类型检查和生产构建通过。
- [ ] 状态机、权限、冻结规则和聚合进度的回归证据已保存。

## 待业务确认

以下结论确定后应直接更新对应验收条目，不再另建说明文档：

1. 未关闭问题是否阻止项目完成；如果阻止，哪些状态或严重程度例外？
2. 项目完成后是否允许补充或纠正交付物元数据？
3. 工作包当前自动完成是否足够，还是必须保留人工验收入口并进入 V2？
